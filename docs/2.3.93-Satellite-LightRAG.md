### [LightRAG](https://github.com/HKUDS/LightRAG)

> Handle: `lightrag`<br/>
> URL: [http://localhost:35040](http://localhost:35040)

LightRAG is a graph-based Retrieval-Augmented Generation server. It ingests documents, extracts entities and relations into a knowledge graph, and answers queries with naive/local/global/hybrid retrieval. It ships a web UI, a REST API and an Ollama-compatible chat endpoint so it can be used as a "model" from other Harbor frontends.

![LightRAG document management UI](./harbor-lightrag.png)

## Starting

```bash
harbor pull lightrag
# Recommended: with a local backend for LLM + embeddings
harbor up lightrag ollama --open
```

The web UI lives at `/webui` and asks for an API key on first load. Enter the value of `HARBOR_LIGHTRAG_API_KEY` (default `sk-lightrag`). The same key is required as `X-API-Key` header for API calls; only `/health` is unauthenticated.

Ingest a document and query it:

```bash
curl -H "X-API-Key: sk-lightrag" -H "Content-Type: application/json" \
  -X POST http://localhost:35040/documents/text \
  -d '{"text":"...","file_source":"note.txt"}'

curl -H "X-API-Key: sk-lightrag" -H "Content-Type: application/json" \
  -X POST http://localhost:35040/query \
  -d '{"query":"What does the note say?","mode":"hybrid"}'
```

Files dropped into `HARBOR_LIGHTRAG_WORKSPACE/inputs` can be ingested with the "Scan" button in the UI.

## Configuration

### Backends

LightRAG needs an LLM and an embedding model. Harbor wires them via cross-files:

- `harbor up lightrag ollama` — LLM and embeddings from Ollama (`HARBOR_LIGHTRAG_OLLAMA_MODEL`, `HARBOR_LIGHTRAG_OLLAMA_EMBEDDING_MODEL`). Pull both models into Ollama first.
- `harbor up lightrag llamacpp` — LLM from llama.cpp via its OpenAI-compatible API (`HARBOR_LIGHTRAG_LLAMACPP_MODEL`). llama.cpp's router does not serve embeddings, so always combine it with an embedder: `harbor up lightrag llamacpp tei`.
- `harbor up lightrag tei` — embeddings from [text-embeddings-inference](./2.2.26-Backend-Text-Embeddings-Inference.md) (`HARBOR_TEI_MODEL`). `HARBOR_LIGHTRAG_TEI_EMBEDDING_DIM` must match the TEI model's dimension (384 for the default `bge-small`).

Without any cross-file, LightRAG uses the generic OpenAI-compatible settings (`HARBOR_LIGHTRAG_OPENAI_URL/KEY`, `HARBOR_LIGHTRAG_MODEL`, `HARBOR_LIGHTRAG_EMBEDDING_MODEL`).

Small models (under ~3B) frequently fail LightRAG's structured entity extraction; graph-based modes (`local`, `global`, `hybrid`) then return "no-context" while `naive` mode still works. Use a 7B+ model for good graph quality.

### Environment Variables

Following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
HARBOR_LIGHTRAG_HOST_PORT=35040                     # Host port for UI and API
HARBOR_LIGHTRAG_IMAGE="ghcr.io/hkuds/lightrag"
HARBOR_LIGHTRAG_VERSION="latest"
HARBOR_LIGHTRAG_WORKSPACE="./services/lightrag/data" # Persistent data root
HARBOR_LIGHTRAG_API_KEY="sk-lightrag"                # X-API-Key for UI and API

# Standalone OpenAI-compatible defaults (used when no backend cross-file applies)
HARBOR_LIGHTRAG_OPENAI_URL="http://llamacpp:8080/v1"
HARBOR_LIGHTRAG_OPENAI_KEY="sk-lightrag"
HARBOR_LIGHTRAG_MODEL=""                             # LLM model name
HARBOR_LIGHTRAG_EMBEDDING_MODEL=""                   # Embedding model name
HARBOR_LIGHTRAG_EMBEDDING_DIM=768                    # Embedding vector size

# Reranker (optional): null, cohere, jina, aliyun
HARBOR_LIGHTRAG_RERANK_BINDING="null"
HARBOR_LIGHTRAG_RERANK_URL=""
HARBOR_LIGHTRAG_RERANK_MODEL=""

# harbor up lightrag ollama
HARBOR_LIGHTRAG_OLLAMA_MODEL="qwen2.5:0.5b"
HARBOR_LIGHTRAG_OLLAMA_NUM_CTX=32768
HARBOR_LIGHTRAG_OLLAMA_EMBEDDING_MODEL="nomic-embed-text:latest"
HARBOR_LIGHTRAG_OLLAMA_EMBEDDING_DIM=768

# harbor up lightrag llamacpp tei
HARBOR_LIGHTRAG_LLAMACPP_MODEL="LiquidAI/LFM2.5-8B-A1B-GGUF:Q8_0"

# harbor up lightrag tei
HARBOR_LIGHTRAG_TEI_EMBEDDING_DIM=384
```

### Volumes

`HARBOR_LIGHTRAG_WORKSPACE` is mounted at `/app/data` and LightRAG runs as your host user, so everything below is host-owned. The `lightrag-init` sidecar chowns the workspace to your host user (`HARBOR_USER_ID`/`HARBOR_GROUP_ID`) before each start, so files stay manageable without `sudo`.

- `rag_storage/<embedder>/` — knowledge graph, vector DBs and KV stores, one directory per embedding source (`openai`, `ollama`, `tei`)
- `inputs/` — drop documents here for scanning
- `prompts/` — custom prompt overrides
- `tiktoken/` — tokenizer cache

## Troubleshooting

```bash
harbor logs lightrag
```

- `Embedding dim mismatch, expected: N, but loaded: M` — the embedding model changed after data was ingested. Harbor keeps a separate store per embedder (`rag_storage/ollama`, `rag_storage/tei`, `rag_storage/openai`) so switching cross-files does not trigger this; it only occurs if you change `HARBOR_TEI_MODEL` or the Ollama embedding model in place. Stop the service, delete the affected `rag_storage/<embedder>` directory, then re-ingest. Also note that small LLMs such as the default `qwen2.5:0.5b` often extract no entities, so `hybrid`/`local`/`global` queries answer `[no-context]` while `naive` works; use a larger model for graph-based modes.
- `403 API Key required` in the UI — enter `HARBOR_LIGHTRAG_API_KEY` in the key prompt.
- `[no-context]` answers in hybrid mode — the LLM did not extract entities; try `naive` mode or a larger model.
